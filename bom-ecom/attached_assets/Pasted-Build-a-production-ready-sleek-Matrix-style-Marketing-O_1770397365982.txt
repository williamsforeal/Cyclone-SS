Build a production-ready, sleek “Matrix-style” Marketing Ops Dashboard web app for a DTC brand.

CORE IDEA
A multi-page UI that centralizes:
1) Airtable-based campaign planning + ad production pipeline
2) n8n automation visibility (status, runs, failures, latency)
3) Creative performance tracking (winning statics, winners by avatar/angle)
4) Asset library (generated images, prompts, variants A/B/C)
5) Reporting dashboard (CAC/ROAS/CTR/CVR mock + placeholders)

STYLE / UI
- Aesthetic: modern “Matrix-lite” (dark UI, neon accents, subtle grid, clean typography)
- Use a sidebar navigation, top search bar, and modular cards.
- Keep it professional and readable (not gimmicky).
- Include “command palette” (Ctrl+K) for quick navigation.
- Use responsive design.

TECH STACK
- Next.js (App Router) + TypeScript
- TailwindCSS + shadcn/ui
- Zustand for client state
- Server actions or API routes for data fetching
- Charts: recharts
- Auth: simple credential-based (dev mode) + placeholder for OAuth later
- Data: Airtable as primary database (via API)
- Optional: store files/asset URLs in S3 (fields in Airtable)

DATA MODEL (Airtable tables)
Assume these Airtable tables exist (create mock adapters if missing):
- Products
- Campaigns
- AdSets
- Ads (Creatives)
- Images (Winning Statics Bank + Generated Assets)
- Jobs (n8n jobs tracking)
- Experiments (A/B/C tests, variants, outcomes)

For each table, define types and build basic CRUD pages:
- list view, detail view, create/edit modal
- filters by product, avatarTarget, awarenessLevel, angle, status, date

PAGES (MULTI-PAGE)
1) Overview Dashboard
   - KPI cards (Spend, ROAS, CAC, CTR, CVR) with mock values and Airtable placeholders
   - “Pipeline health”: n8n jobs today, failures, avg runtime
   - “Creative winners”: top 10 winning ads with thumbnails + tags
   - “Campaign calendar”: upcoming launches

2) Campaign Builder
   - Create campaign: product, offer, objective, targeting, budget, dates
   - Generate ad concept briefs: hook/headline, angle, avatar, awareness
   - Button: “Send to n8n” (calls an API route that triggers webhook to n8n)

3) Creative Lab
   - A/B/C generation panel:
     - shows ad concept inputs
     - shows prompt compiler output (variants)
     - shows generated images + status
   - Ability to approve/promote creative to “Ad Set”
   - Store prompt + reference image URL + outputs in Airtable

4) Winning Ads Library
   - Grid of winning statics
   - Filters: avatarTarget, angle, awarenessLevel, “why it won”, tags
   - “Pattern extraction” panel: show aggregated patterns from winners

5) Experiments (A/B/C Tests)
   - Table of experiments by recordId
   - Each experiment has A/B/C variants with status + results
   - Add fields: hypothesis, primary metric, winner, notes
   - Visual compare view: A vs B vs C side-by-side

6) Ops / Automations (n8n)
   - Show list of recent n8n runs (from Airtable Jobs table or webhook logs)
   - Status: success/fail, time, payload preview, output preview, error message
   - Retry button (calls API route -> n8n webhook with run_id / recordId)
   - “Dead letter queue” view for failed jobs

7) Settings
   - Airtable API key + base ID config (use env vars)
   - Webhook endpoints for n8n + fal.ai
   - Feature flags: enable storybrand variant, enable winners injection, etc.

INTEGRATIONS
- Airtable:
  - build a lightweight data layer: /lib/airtable.ts
  - support read/write records
- n8n:
  - expose /api/webhooks/trigger
  - send payload to n8n webhook (campaign/creative generation)
  - store job status in Airtable Jobs table
- fal.ai:
  - keep as placeholder endpoint calls (do not hardcode secrets in client)
  - store generation outputs (image URLs) into Airtable Images table

N8N WORKFLOW MAPPING (EXPLAIN IN-APP)
Create an “Automation Map” section (in Ops page) describing each pipeline stage:
- Stage 1: Airtable concept intake (adType, headline, concept, cta, angle, avatarTarget, awarenessLevel, tags)
- Stage 2: Product image extraction + S3 upload (reference image URL)
- Stage 3: Prompt compilation (Message a Model) generates A/B/C variants JSON
- Stage 4: fal.ai render (prompt + reference image URL)
- Stage 5: Upload outputs to S3, write back to Airtable
- Stage 6: Mark experiment + winners

Create UI components that display:
- inputs
- outputs
- status
- timestamps
- errors
- links to generated assets
